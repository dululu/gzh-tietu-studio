# 贴图排版手册 · 公众号贴图工坊

> 这份手册回答两件事：**这套图为什么长这样**（骨架），**换选题时改哪里**（变体）。
>
> 想知道「怎么用」（安装、命令、全字段、配图流程、FAQ），看 [`../说明书.md`](../说明书.md)。

## 一、骨架：90% 是不动的

画布 **810 × 1080**（精确 3:4），导出 2 倍图 = **1620 × 2160**。公众号贴图建议上限 1080×1440，这是同比例。

从上到下 5 个槽位，只有第 4 个会换：

| # | 槽位 | 是否固定 | 规格 |
|---|------|---------|------|
| 0 | 水彩底 + 白色圆角卡片 | **固定** | 卡片内缩 26px，圆角 26，水位蓝白渐变 |
| 1 | 右上角账号角标 | **固定** | 88×88，深蓝 `#10294B`，两字上下 + 分隔线 |
| 2 | 主标题（两行） | **固定** | 第一行 72px，第二行 58px + 淡蓝雾带 |
| 3 | 副标题 | 可选 | 32px 宋体粗，下方 1px 分隔线 |
| 4 | **内容区** | **每篇都换** | 占满剩余高度 |
| 5 | 底部来源 | 可选 | 16px 灰 `#7A8798` |

**这就是效率的来源**：一张图里真正需要"设计"的只有内容区，其余四个槽位是模板件，改文案就行。

### 主标题的三条硬规则

1. **两行，一轻一重**。上句 72px 给背景/定性（4–7 字），下句 58px 给反差/悬念（6–10 字）。
2. **雾带只压第二行**。淡蓝色横向渐变条横贯卡片、两端渐隐，视觉焦点自动落到"结论"那句。
3. **字号自适应**。模板会按容器宽度逐像素缩字号，文字写长了不会折行、不会溢出。

### 五套配色：改一个字段就换

所有颜色都收在 **`主题.js`** 里，PNG 和 SVG 两条路读的是同一份定义。数据里写 `"theme": "red"` 即可换色。

| key | 名字 | 底色 | 强调色 | 适合 |
|---|---|---|---|---|
| `blue` | 蓝白 · 默认 | 水彩蓝白 | 深蓝 + 橙 `#E8622A` 高亮 | 通用、财经、数据 |
| `red` | 中国红 · 金榜 | 暖白偏粉 | 深红 `#7A1F1B` + 金 `#C9971A` | 高考放榜、喜报、政策 |
| `green` | 墨绿 · 理性 | 青白 | 墨绿 `#0F3A2E` + 橙 `#E8663E` | 分析、避坑、长线建议 |
| `amber` | 暖橙 · 米色 | 米黄 | 深棕 `#6B4318` + 松绿 `#3E8E7E` | 志愿、选择、经验帖 |
| `ink` | 墨黑 · 极简 | 灰白 | 纯黑 `#111111` + 朱红 `#D94F2B` | 观点、时评、严肃话题 |

**加第六套配色**：只要在 `主题.js` 里加一个 key，模板和导出脚本都不用改。

蓝白主题的完整色值（其余主题同结构，直接看 `主题.js`）：

| 用途 | 色值 |
|---|---|
| 主标题 / 副标题 | `#16324F` |
| 柱体渐变 | `#0F2E52` → `#1D4E80` |
| 折线 | `#2FBF8F` |
| 高亮柱 | `#E8622A`（同色填充+描边） |
| 横向条形 | `#2E7DD1` |
| 焦点胶囊橙 | `#FF7A45` → `#F2451B` |
| 角标 / 数字卡 | `#10294B` / `#16365C` |
| 来源、注释 | `#7A8798` |
| 水彩底 | `#B9D8F2` → `#F6FAFD` |

规范做法是**一张图只用 1 个强调色**。参考图里每张都只出现一个彩色焦点（粉、橙、蓝），其余全是同色系灰阶。

## 二、标题公式：五种已验证的句型

| 结构 | 例 | 心理机制 |
|---|---|---|
| 疑问 + 解答 | 王兴兴为什么不笑？＋ 原因找到了 | 开环再闭合，逼你点开 |
| 定性 + 事实 | 顶级财富信号 ＋ 李嘉诚巴菲特同时换赛道 | 先给判断，再用名人坐实 |
| 反差对照 | 越南"用工荒" ＋ 中国厂长月薪 2 万 | 一个场景两个地域，落差即钩子 |
| 现象 + 疑问 | 全球财富大洗牌 ＋ 谁在 AI 时代疯狂造富？ | 大背景 + 代入式发问 |
| 陈述 + 惊人类比 | 中国博士数量 ＋ 比驴还多了 | 把抽象数字翻译成荒诞感 |

**共同点**：上句都不给结论，下句才给。这就是"前 14 字定生死"在贴图上的用法——用户划过时只看到前 6–10 个字。

## 三、15 种版式 → 选题映射

选版式只需要回答一个问题：**你要给读者看的是"一件东西""一组数""一个比较"还是"一步步怎么走"？**

| 版式 | 长什么样 | 什么时候用 | `layout` |
|---|---|---|---|
| **单数字冲击** | 一个巨大数字占满内容区，下面挂说明 | 全篇只有 1 个数字是重点（133.31 万、录取率） | `stat` |
| **编号清单** | 编号卡片列表，1/2/3 条 | 结论是"几个信号 / 几个变化 / 几条建议" | `list` |
| **左右对比** | 左浅卡右深卡，各挂 4 条要点 | A 和 B 二选一（省内 vs 外省、新高考 vs 老高考） | `compare` |
| **对峙对比** | 左右两栏各压一个**结论词**，中间 VS 徽章，底部补"适合谁" | 二选一、且**能各用一个词总结**（先宽后窄 vs 一步到位） | `vs` |
| **编号行动卡** | 大号实心色块编号 + 标题 + 倾斜动作标签，卡片可标警示红 | 结论是"这几件事分别要干什么"（要办 / 留意 / 别信） | `cards` |
| **四步阶梯** | 卡片逐级右移 34px 形成台阶，末级主题色反白 | 有先后推进关系，**末级是落点**（从下车到入住） | `steps` |
| **时间轴** | 左侧年份，中间竖线，右侧事件 | 政策沿革、发展脉络（新高考十年） | `timeline` |
| **双轴柱线图** | 柱线双轴，末柱高亮 | 两个指标随时间走，想突出某一年 | `chart` |
| **横向条形 + 数字卡** | 横向条形，右侧并排一张数字对比卡 | 结论是"谁比谁多"，要一个冲击性对比 | `bar` |
| **单图 + 图注** | 一张现场大图，下面一句图注 | 有一张能说明一切的图（发布会、现场照、截图） | `photo` |
| **主图 + 圆形焦点** | 图上叠一个圆，圈住要强调的信息 | 图里有具体数字/条件，不圈出来读者会漏 | `photoFocus` |
| **双主体 + 金句 + 四宫格** | 两个主体并置，下面一句金句，再拆成 4 格（格子里可放图） | 抽象判断要落地（"他布局了哪 4 个方向"） | `duo` |
| **大图压标题** | 大图铺满内容区，底部渐变上压一句大字结论，图下三张短要点卡 | 有一张好图，且**结论本身就是最好的标题** | `hero` |
| **巨型字主视觉** | 一个 210px 的巨型字吃掉整行、下半段压一条满幅色块垫、整块转 -3° | **结论能压到 1 个字或一个短词**，想让读者先记住"那个字"（撤销 / 缺人 / 没赶上） | `bigword` |
| **横向色带分割** | 画面切成 2–4 条满幅出血、零间距、等高的横向色带 | 条目**并列且要一眼扫完**，想让整张图显得"满"（三类清退方向、三条原因） | `band` |

选择顺序建议：**先看手上有什么素材**（有图 → `photo` / `photoFocus` / `duo` / `hero`；
纯数 → `stat` / `chart` / `bar`；纯文字 → `list` / `cards` / `compare` / `vs` / `steps` / `timeline` /
`bigword` / `band`），
**再看想让读者记住什么**（记住画面 → `photo` / `hero`；记住数字 → `stat` / `bar`；
记住观点 → `duo` / `list`；记住顺序 → `timeline` / `steps`；记住二选一 → `compare` / `vs`；
**记住一个字 → `bigword`；记住一张"满"图 → `band`**）。

**几对容易混的版式，怎么分：**

| 两两 | 分界线 |
|---|---|
| `compare` vs `vs` | `compare` 是"两条各 4 条要点，你自己比"；`vs` 是"两条路我先各用一个词总结给你" |
| `list` vs `cards` | `list` 竖着扫一列编号；`cards` 每张卡是封闭单元，右上角动作标签直说"这条要干什么" |
| `timeline` vs `steps` | `timeline` 是一条竖线串起的**时间顺序**；`steps` 强调一步比一步更靠后的**推进关系**，末级反白当落点 |
| `photo` vs `hero` | `photo` 是"图 + 图下一行注"，标题在卡片顶部；`hero` 把结论**压在图上**，让图直接承载观点 |
| `stat` vs `bigword` | `stat` 是"一个数字 + 说明"的**信息图**（数字最大 170px，靠字号取胜）；`bigword` 是"一个字就是画面主体"的**海报**（210px + 色块垫 + 倾斜），**数字只是顺带**。要用大字讲数字就选 `stat`，要用大字讲**词**（撤销 / 内卷）才选 `bigword` |
| `cards` vs `band` | `cards` 是**有间距的圆角卡片**，每张卡自成一格、适合"要做的事"；`band` 是**零间距满幅色带**，条目之间没有边界、适合"并列的分类"。卡片要"一条一条看"，色带要"一眼扫完" |

### 海报化的视觉手段（`vs` / `cards` / `steps` / `hero` / `bigword` / `band` 六个版式在用）

版式做"信息图"容易偏平，做"海报"才抓眼。这六个版式共用一套海报语言，改版时可沿用
（来源与完整案例拆解见同目录 `视觉海报案例学习笔记.md`）：

- **反差排第一** —— 全图只留 1–2 个视觉锚点，其余都让位。`cards` 的编号从"54px 淡色水印"改成
  **74×74 实心色块**，就是因为"淡"等于没有重点。
- **色块分割** —— 每张卡左侧压 8px 主题色条、`vs` 两侧顶部压 8px 色条、`band` 整条色带铺满，
  靠色块切分视线，不靠描边。
- **满幅出血 > 缩在版心内** —— 这是"色块"和"海报"的分界线。`bigword` 的色块垫和 `band` 每条色带
  都左右各出 50px（正好顶到卡片内边距外，从 x=26 到 x=784）。不出血的色块看起来像"文本框底色"。
- **直角色块 > 药丸** —— 标签、结论词用 6–8px 圆角的硬边色块，比全圆角胶囊更有"运营海报"的力。
- **零间距装配** —— `band` 的色带之间不留 gap、不留圆角，才是"分割"；留了缝就退回"卡片列表"。
- **倾斜贴纸** —— `cards` 的动作标签转 -4°、`vs` 的 VS 徽章转 -7° 并加白色外环、`bigword` 的
  巨型字转 -3°。倾斜量要小（≤8°），大了就变成"歪"而不是"跳"。**全图角度固定这三档，不再新增**。
- **色块编号统一语言** —— `cards`（74px 方块）、`steps`（54px 方块）、`hero` 图下卡（40px 数字）、
  `band`（76px 反白数字）用的是同一套"实心/反白 + 数字"，一张图里出现两种编号样式会打架。
- **色彩编码** —— 警示一律用**固定警示红 `#CE4038`**（配 `#FCEDEA` 底），刻意脱离主题色：
  警示不该跟着配色走，否则在同一套暖色里会被读漏。
- **大字主视觉** —— `hero` 的压图结论 54px + 下半 36% 半透明白高亮块；`bigword` 的 210px 巨型字 +
  下半压 `--soft` 色块垫。字大到"字就是图"才算主视觉，放大到"能看清"是不够的。
- **等高优先于按内容分配** —— `band` 的色带用 flex 等分，不按文案长短给高度。高矮不齐就变成"表格"了。
  所以色带里的 `p` 有字数红线（见六节）。
- **字数红线跟着字号走**：字号变大 = 能放的字变少。改版式时**同步收紧文案**，
  比如 `steps` 末级最窄，`p` 就得从 24 字压到 20 字。

### 版式和配色的组合建议

不是所有组合都好看。稳妥的搭法：

| 选题类型 | 推荐版式 | 推荐配色 |
|---|---|---|
| 高考政策 / 放榜 | `timeline`、`stat` | `red` 中国红 |
| 志愿选择 / 避坑 | `compare`、`list` | `amber` 暖橙 |
| 数据分析 / 趋势 | `chart`、`bar` | `blue` 蓝白 |
| 大学热点 / 时评 | `stat`、`photo` | `ink` 墨黑 |
| 长期发展 / 理性建议 | `list`、`compare` | `green` 墨绿 |

## 四、六种用法

### 用法 1：出一张（最常用）

双击 `贴图模板.html`，用 Chrome 打开。

1. 底部文本框里是全部内容（JSON 格式）
2. 上方两个下拉框分别切换 **版式** 和 **配色** —— 会自动改写 `layout` / `theme` 字段
3. 改完点「重新渲染」
4. 点「下载 PNG（2 倍图）」，得到 1620×2160

下拉框右边的 5 个小色块是当前配色的取样（角标 / 标题 / 条形 / 折线 / 高亮），换色时扫一眼就知道搭不搭。

操作区不会出现在导出的图里。

### 用法 2：批量出图（写好数据，一次出 N 张）

把每张图的内容写进一个 JSON 数组，然后：

```bash
cd gzh-tietu-studio

# 用脚本（推荐，终端直接调 Chrome）
./批量出图.sh examples/数据-九种版式示例.json 贴图输出

# 或者纯 Node（本机权限正常时）
node 批量出图.js examples/数据-九种版式示例.json 贴图输出

# 要显式指定模板时（一般不用，脚本会自己判断）
./批量出图.sh examples/数据-九种版式示例.json 贴图输出 --template=贴图模板.html
```

**不用手写 `--template`**：脚本看数据里有没有 `layout` 字段 —— 有就自动用 `贴图模板.html`，没有才退回老的 `信息图模板.html`。这条是踩过坑才加的（见第八节第 9 条）。

数据源里每个元素的 `name` 决定输出文件名，其余字段全部透传给模板。**同一批可以混用版式和配色**——A 图用 `stat`+`red`，B 图用 `bar`+`blue`，互不影响。

`examples/数据-九种版式示例.json` 里已经有 9 条（每种版式一条，覆盖 5 套配色），直接改成你的内容即可。

### 用法 3：配图（三个版式需要，四宫格可选）

`photo` / `photoFocus` / `duo` 三个版式要用图。其中 `duo` 的**四宫格默认也要给图**
（`quadImgs`，四张一起给）——不给就退回「首字大卡」：四个色块各压一个大号汉字，
那是模板的兜底样式，不是常用样式（见第六节 `duo` 字段表）。其余六个版式纯文字/图表，留空也不影响。

`img` / `img2` 填**相对路径、绝对路径或网址**都行（`批量出图.sh` 会把相对路径转绝对，避免子目录里解析不到）：

```json
"img": "img/TOPIO_3_3.jpg",
"img2": "https://example.com/b.jpg"
```

**配国内题材时优先找中国场景的图**：维基共享支持中文关键词（`node 找图.js search "汉服"`、
`cat "Textile industry in China"`），里面有大量中国摄影师拍的校园、汉服、织物、文物；
Pexels 基本只有欧美/东南亚场景，配国内选题会"不像我们的学校"。
微博 / 小红书 / B站 / 百度图片**不要直接扒**（没有开放接口，默认保留全部权利），
要用就走"自己截图 / 官方媒体图标来源 / 拿到授权"三条路。完整说明见说明书 4.1.1。

找不到的图会在命令行里列出来（不会静默变成空白），页面上渲染成虚线占位块，方便先排版后补图。

#### 从开放图库取图（免费 + 可商用）

```bash
# 维基共享资源 —— 题材最广，技术、人物、地点、事件都有
node 找图.js search "humanoid robot" 8          # 全文搜，自动只留大横图
node 找图.js cat "Humanoid robots" 8            # 按分类取，更精准
node 找图.js get "File:TOPIO 3 3.JPG" img 1600  # 下载到 img/

# NASA 图库 —— 航天/科技向，公有领域
node 找图.js nasa "robot arm space station" 8   # 搜
node 找图.js nasa-get "iss071e361950" img 1600  # 按 nasa_id 下载，自动缩图

# Pexels —— 现代实拍照片，校园/实验室/职场人像最好用
node 找图.js pexels "university students campus" 8   # 搜（固定只出横构图）
node 找图.js pexels-get "8199659" img 1600           # 按 id 下载到 img/，自动按需缩图
```

三源都免费可商用，Pexels 要 key（放哪见下面「Pexels key 放哪」）。

**下载偶发超时是正常的**：维基把缩略图挪到了新的 `thumb.wikimedia.org`，本机到它时不时会 ETIMEDOUT
（同一张图 curl 能下、node 卡住的情况也出现过）。`找图.js` 现在接口查询和下载都带 3 次重试 + socket 超时，
失败时会**删掉半截文件** —— 留一个 0 字节的同名图最坑，页面里看起来就是一张破图，还查不出原因。

| Pixabay / Unsplash | ❌ 要 key | 接口通 | 同类备选，注册免费；Pexels 够用就先不接 |
| Smithsonian | ❌ 要 key | 接口通 | 博物馆藏品，注册免费 |

**结论**：免 key 顺手的是**维基共享 + NASA**，现代照片质感靠 **Pexels**。三个美术馆对科技/高考题材没用，但你要写「古文字学」「非遗保护」「考古」这类文科专业选题时，它们是 CC0 且画质极好的来源。

下载时会把**标题、作者、许可、许可链接、原页**一并打印出来。维基共享资源上的图绝大多数是 CC BY / CC BY-SA / 公有领域：
- **CC BY / CC BY-SA**：可商用，**必须署名**（作者 + 许可名）
- **CC0 / 公有领域**：随便用，仍建议标来源
- 标着 **NC / ND** 的一律不要用
- NASA 绝大多数是公有领域，署名写 `NASA` 或 `NASA/JSC` 这种即可
- **Pexels**：可商用、免署名（标了更好），但**不得转售原图**、**不得暗示照片中的人为你/某机构背书**。foot 写法：`图片：摄影者 / Pexels`

#### Pexels key 放哪

key 写死在脚本里迟早会漏出去，所以按顺序找：环境变量 `PEXELS_API_KEY` → `~/.workbuddy/pexels.key` → 项目内 `.pexels-key`。

```bash
echo "你的key" > ~/.workbuddy/pexels.key && chmod 600 ~/.workbuddy/pexels.key
```

放在**用户目录**而不是项目目录，是为了不跟着项目被提交/分享出去。key 在 https://www.pexels.com/api/ 免费申请，每月 20000 次请求，一个人用不完。

**Pexels 的短板**：中文语境差。搜"校园"出来的基本都是欧美校园（古典图书馆、草地、西方面孔），没有国内大学实拍。所以用它配图时，图注要写"示意图"，别写成"某校现场"——既避免误导读者，也符合它"不得暗示背书"的条款。

#### 配图的硬规矩

1. **署名写进 `foot` 字段**，格式：`图片：作者，许可，来自维基共享资源`（Pexels 写 `图片：摄影者 / Pexels`）。这是许可的使用条件，不是礼貌。
2. **图必须和内容对得上**，别拿一张泛泛的科技图去配一条具体政策。
3. **别把图当"现场照"用**。开放图库里的图多半是通用题材（人形机器人、机房、晶圆），不能暗示成"某某大学实拍"。图注写描述性文字，不要写"XX 大学现场"。
4. 各版式对图的要求不一样：

| 版式 | 画面位置 | 选图建议 |
|---|---|---|
| `photo` | 满宽大图，约 658×600（横构图） | 主体在中间偏上，裁掉上下都不影响 |
| `photoFocus` | 中间被 480px 白圆盖住 | **主体不要放正中**，让有辨识度的部分留在圆外一圈 |
| `duo` 主体 | 两张方图，各 320×272，按顶部对齐裁 | 主体靠上；两张色调别差太远 |
| `duo` 四宫格 | 四个小方块，各约 152×142（**接近 1:1**） | 保留率：4:3 留 81%、3:2 留 72%、**2:3 竖图留 70%**，竖图也能放。主体要在中央，或配 `quadPos` 挪进画面 |

5. **图多的时候，署名只列需要署名的那几个**。四宫格 + 双主体最多 6 张图，脚注**最多 3 行**（一行约 41 个汉字 / 76 个西文字符），超了会折行、把内容区顶小。规则是：
   - CC BY / CC BY-SA：**必须署名**（作者名）
   - CC0 / 公有领域：不强制署名。图多时可以不占行，完整来源写进 `examples/CREDITS.md` 留档即可
   - 作者只列前 2 个 + 「等」，许可名合并成一组 `CC BY-SA 3.0/4.0`
   - 这一行有现成的生成器：`node 署名行.js 数据源.json` 会扫出数据里真正用到的图、
     去台账查作者与许可、拼好这行，并报出占多少字宽；**超 41 会自动收窄作者、给出放得下的版本**

6. **脚注只写来源、作者、许可名三样，别把许可条款抄进去**。`配图：维基共享资源 · N509FZ；CC BY-SA 4.0` 就够了。
   CC BY-SA 的图照常裁剪使用，但**「经裁剪，按相同许可发布」这类话不要写进脚注**——读者看不懂，
   它是要留档的事实而不是要给读者看的信息。裁剪与相同许可记在 `配图署名.md` 台账里，需要追溯时查台账。
   - 能选就优先 **CC BY / CC0 / 公有领域**（署名更短，也没有再许可的负担）
   - 商业投放、品牌稿这类正式场合，换成 Pexels（免署名、可商用、可裁剪）或自采图

`photoFocus` 最容易翻车：白圆几乎盖满画面，选一张主体正好在中间的图（比如人像特写），圆一压就全没了。
而**四宫格最容易翻车的是"主体被裁掉了"**——小方块是 1:1，一张 3:2 的横图要裁掉两侧约 28%，主体在两侧就直接消失。
真图数现在出图时自动报（`图 6/6 张`）；某格是空的会写成「缺图」，同时说明路径写错了。

### 用法 4：导出 SVG，拖进 Figma 里改

同一份数据源可以导出**可编辑矢量**，而不是只能垫底的图片：

```bash
node 导出SVG.js examples/数据-九种版式示例.json svg输出
```

`svg输出/` 里会得到 9 个 SVG + 一个 `_预览.html`（浏览器打开能一次看完 9 张，也是给 Figma 挑图用的对照表）。**用鼠标直接拖进 Figma 画布**即可，进去之后：

| 元素 | 在 Figma 里是什么 |
|---|---|
| 标题、副标题、图注、数字 | 可编辑文本框 |
| 卡片、角标、柱子、条形、圆形 | 可编辑矢量图形（可改宽高、圆角、颜色） |
| 折线 | 矢量路径，可拖动节点 |
| 水彩底 | 渐变填充，可在 Fill 面板调色标 |
| **照片** | 已按 base64 内嵌的 `<image>`，自带圆角裁切，不用手动置位 |

**照片是内嵌的**，所以 SVG 会明显变大（一张带 6 张图的 duo 约 700KB）。内嵌前会自动按目标宽度压一遍
（`sips` 缩到最长 1200px、JPEG 质量 72），不然原图直塞能到几十 MB，Figma 打开就卡死。

两个已知限制：

- **裁切位置只有三档**。HTML 里 `quadPos` 支持 `12% center` 这种精确百分比，SVG 只有左/中/右
  （`xMinYMid` / `xMidYMid` / `xMaxYMid`）。要精修就在 Figma 里拖图片。
- **外链图不内嵌**。`img` 填网址的不会转 base64，导出时会在命令行列出来，SVG 里留虚线占位框。要内嵌就先 `找图.js` 下到本地。

**导入后建议做三件事**：

1. **替换字体**。SVG 里写的是 `Songti SC` / `PingFang SC`。如果 Figma 提示字体缺失，把标题层统一换成 **思源宋体 Source Han Serif**（或 `Noto Serif SC`），正文换成**苹方 PingFang SC**，观感基本不变。
2. **打成组件**。把整张图 Ctrl+Alt+K 建成 Component，以后复制实例改文字，版式不会跑偏。
3. **图层已经分好组**：`背景`、`账号角标`、`主标题`、`内容区-xxx`、`来源注释`，直接对着组名找。

**什么时候用哪条路**：

- 要**发布**（文章配图、贴图）→ 走 PNG，`批量出图.sh` 出 2 倍图
- 要**二次设计**（换配色、调间距、加元素、做系列变体）→ 走 SVG，拖进 Figma

两条路读的是同一个 JSON，改数据只需改一处。

### 用法 5：生成总览页（一次看完一批）

出一批图之后想知道整体观感，用这个：

```bash
node 生成总览.js examples/数据-热点示例.json 热点出图 "09·14 热点贴图"
```

会在输出目录里生成 `_总览.html`，3 列网格引用同目录的 PNG，右上角标了每张的 `layout · theme`。缺图会标红框并在命令行列出是哪些。

想连总览图一起存成 PNG，跑配套脚本：

```bash
./总览截图.sh 热点出图          # 默认 1204 宽、1.5 倍
./总览截图.sh 热点出图 1204 2   # 需要更大就调宽度和倍率
```

**不要写死 `--window-size` 的高度**：总览页高随张数变化（几张一行、共几行），固定值不是底部留一大片底色，就是最后一行被截断。脚本先让页面报出 `documentElement.scrollHeight` 再截。两个要点：

- **量高和截图必须同宽**。宽度决定网格列宽和换行，进而决定页高。
- **探针页必须和 PNG 同目录**。`_总览.html` 里图片是相对路径 `./xxx.png`，挪到临时目录会全部 404，`img` 高度塌成 0，量出来的页高就成了"少一行"的。

### 用法 6：回读校验（检查溢出 + 真图清点）

```bash
./检查溢出.sh 热点出图     # 重看结论：读缓存，一次 Chrome 都不启
```

**默认不用单独跑这一步**——出图那一趟已经把它做完了（探针见用法 2），结论直接印在出图结果里；
这条命令是给"回头重看上次结论"用的。

逐张量 `.content` 的 `scrollHeight - clientHeight`，把"内容顶出固定高度、盖到页脚上"这种
肉眼看图几乎发现不了的问题变成一行结论：

```
01_小学在消失_单图_墨黑        ✅ 放得下  内容区 +0px  卡片 +0px  画布 +0px   图 1/1 张
09_双主体加四宫格_墨绿         ⚠️ 溢出   内容区 +17px  卡片 +0px  画布 +0px   图 6/6 张
```

超出 4px 以内算通过（落在卡片 40px 的底部内边距里，不构成遮挡）。**`duo` 是最容易出问题的版式**，
它的主体图、金句、四宫格都是固定高度，加起来可能超过内容区。

## 五、五项自动适配（写长了不会崩）

模板会自己处理排版，不用手动数字号：

| 位置 | 上限 | 下限 | 行为 |
|---|---|---|---|
| 标题第一行 | 72px | 24px | 单行，超宽逐像素缩字号 |
| 标题第二行 | 58px | 24px | 同上，另带雾带 |
| 副标题 `deck` | 32px | 22px | 优先单行；缩到 22px 还放不下才允许折行 |
| 单数字 `statValue` | 170px | 24px | 与单位一起居中 |
| 单数字说明 `statLabel` | 30px | 20px | 优先单行，同上 |

**实践结论：副标题控制在 15 个汉字内、单数字说明控制在 19 个汉字内，字号就不用缩**，观感最好。超了也不会坏，只是字变小。

`compare` 两栏的要点建议 **各 12 个汉字以内**——两栏各占一半宽度，超过就会折行，两行三行混在一起会显得参差。

| 字段 | 说明 |
|---|---|
| `listTitle` | 清单标题 |

**`compare` 左右对比**

| 字段 | 说明 |
|---|---|

两栏要点条数建议一致（各 4 条），条数不同时两边会自动均分高度、不会错位。

**`timeline` 时间轴**

| 字段 | 说明 |
|---|---|

**`photo` 单图**

| 字段 | 说明 |
|---|---|
| `img` | 图片路径 |
| `cap` | 图注 |

**`photoFocus` 圆形焦点**

| 字段 | 说明 |
|---|---|
| `img` | 主图路径 |
| `pills` | 胶囊文字数组，建议 1–2 条，如 `["20000-40000元/月"]` |
| `cap` | 图下方小字说明 |

**`duo` 双主体 + 四宫格**

| 字段 | 说明 |
|---|---|
| `img` / `img2` | 两个主体图 |
| `quote` | 金句 |
| `quads` | 四宫格标签数组，**必须 4 项** |
| `quadImgs` | 四宫格每格的图，数组，按顺序对应 `quads`。**默认给满 4 项** |
| `quadPos` | 可选。每格图的裁切位置，如 `["center","center","center","72% center"]` |

`quadImgs` **默认给满四张**——给了才是「图 + 标签」，这是常用样式。**不给**就退回「首字大卡」
（彩色底 + 一个大号汉字 + 标签），那是模板的兜底样式。真要空着（那格本来就是抽象概念、
找不到对得上的图），**四格一起空**，让整行统一；只给一两张会一眼看出是漏配。

另外：**宫格格子约 152×142（近方形）**，`object-fit: cover` 下保留率只看原图长宽比——4:3 横图留 81%、
3:2 留 72%、2:3 竖图留 70%，三者差别很小，**竖图放宫格没问题**（居中裁，主体在画面中部即可）。
真正吃画幅的是 `duo` 的**主体**画框 320×272 配 `object-position: top center`，**16:9 宽幅图只留 66%**。

`duo` 一共 6 张图（2 主体 + 4 宫格），**脚注额度会被挤掉**：`foot` 最多 3 行，
署名行写不下就只列主体图的作者 + 「等」，完整名单放进项目的配图署名台账。

`quadPos` 是给正方形格子用的：格子是 1:1，横图两侧必被裁掉，主体偏左/偏右时用百分比把它挪进画面
（`0% center` 取最左、`100% center` 取最右）。不写就是居中裁。

`duo` 是唯一一个**最多能放 6 张图**的版式（2 主体 + 4 格），所以它也是唯一需要留意
来源署名长度的版式——见下面「配图的硬规矩」第 5 条。

**`vs` 对峙对比**（2026-09-16 新增）

| 字段 | 说明 |
|---|---|
| `vsTitle` | 内容区小标题（居中） |
| `vsMid` | 中间徽章的文字，默认 `VS` |
| `vsLeftTag` / `vsRightTag` | 左右两侧的**结论词**，直角色块标签。各 ≤ 5 汉字 |
| `vsLeftTitle` / `vsRightTitle` | 两侧小标题（40px 宋体）。各 ≤ 5 汉字 |
| `vsLeftItems` / `vsRightItems` | 两侧要点数组，各 3 条、每条 ≤ 11 汉字 |
| `vsLeftFit` / `vsRightFit` | 两侧底部"适合谁"，实心胶囊标签。≤ 12 汉字 |

左侧是白卡 + 顶部主题色条，右侧是主题色卡 + 顶部白色条（深浅对照）。中间 VS 徽章 68px、转 -7°、
带白色外环。**结论词是这个版式的灵魂**——写不成一个词（"先宽后窄""一步到位"）就别用 `vs`，退回 `compare`。

**`cards` 编号行动卡**（2026-09-16 新增）

| 字段 | 说明 |
|---|---|
| `cardsTitle` | 内容区小标题 |
| `cards` | 数组：`{ "n": "01", "tag": "要办", "h": "标题", "p": "解释", "warn": true }` |
| `cards[].n` | 卡片编号，留空自动按 `01` / `02` 补齐 |
| `cards[].tag` | 右上角动作标签（要办 / 留意 / 别信…），转 -4° 的倾斜贴纸 |
| `cards[].warn` | `true` 时整卡变警示样式（固定警示红 `#CE4038` + `#FCEDEA` 底） |

编号是 74×74 的**实心色块**（不是淡色水印），左边一条 8px 主题色条。`h` ≤ 14 汉字（右边还要放标签），
`p` ≤ 25 汉字（超了自动折第二行）。

**`steps` 四步阶梯**（2026-09-16 新增）

| 字段 | 说明 |
|---|---|
| `stTitle` | 内容区小标题 |
| `stItems` | 数组：`{ "t": "到校前", "h": "信息前置", "p": "一行解释" }`，建议 4 条 |

每级比上一级右移 34px 形成台阶，序号是 54×54 圆角方块，**末级自动用主题色反白**当落点。
`t` 和 `h` 排在同一行，所以 `h` ≤ 6 汉字；`p` ≤ 24 汉字（末级最窄，超过会折行、把卡片撑高）。

**`hero` 大图压标题**（2026-09-16 新增）

| 字段 | 说明 |
|---|---|
| `img` | 主图 |
| `heroTitle` | **压在图上**的结论，54px，下半垫一条半透明白色高亮块。≤ 14 汉字 |
| `heroLead` | 结论下面一行补充，可省 |
| `heroItems` | 图下三张短要点卡，**固定 3 条**：`{ "h": "小标题", "p": "一行解释" }` |

`heroItems[].h` ≤ 8 汉字（一格只有 178px 可用宽）、`.p` ≤ 14 汉字（会折第二行）。
**底部 72% 会压渐变遮罩 + 白字**，选图要选"重点在上半部"的；照片画框约 658×420，
4:3 图裁掉约 17%、3:2 裁掉约 12%（比 `photo` 的 658×600 温和）。

**`bigword` 巨型字主视觉**（2026-09-16 晚新增）

| 字段 | 说明 |

## 七、账号名要改的话

角标内容现在由数据里的 **`badge` 字段**控制（默认「小铭想」），不用改 HTML：

```json
{ "badge": "小铭想" }
```

规则是**第一个字单独一行，剩下的字第二行**，中间自动加分隔线；3 字及以上会自动缩字号，4 字以内都不会溢出。

要连角标底色一起改，改 `主题.js` 里对应主题的 `badge` 色值即可。

## 八、十八个坑（都踩过）

改这套东西之前先看一遍，能省掉大半的排查时间：

1. **模板里删 `<script>` 要小心**。`贴图模板.html` 依赖两个外部脚本：`./vendor/echarts.min.js`（图表）和 `./主题.js`（配色）。少任何一个，对应部分会**静默空白**而不报错。模板里已经放了兜底提示：`主题.js` 缺失会整页红框报错，`echarts` 缺失会在图表位置显示虚线占位框。
2. **`批量出图.js` 会把 `./` 相对路径改写成绝对 `file://`**。因为生成的页面在 `输出目录/.pages/` 子目录里，直接搬过去的相对路径必然 404。根目录下的小模块会被**内联**进页面，`vendor/` 下的则改绝对路径。
3. **Chrome 截完图不会自己退出**，脚本靠"文件大小连续两次不变"判断完成再强杀进程。
4. **每张图要用全新的 profile 目录**。上一张被强杀后残留的 `SingletonLock` 会让新 Chrome 直接退出、不出图。
5. **Chrome 不能从 Node 子进程里启动**（受限沙箱下会被拒）。所以有 `.sh` 和 `.js` 两条路：`批量出图.sh` 由终端直接调 Chrome，绕开子进程限制。
6. **`img` 写相对路径在 `.pages/` 子目录里必然 404**。`批量出图.js` 现在会自动把相对路径解析成绝对路径，找不到的会在命令行列出来。**加了新的图片字段（如 `img3`）不用改脚本**——按 `img` / `img1` / `img2`… 的命名规则自动识别。
7. **别用 `scrollWidth` 判断居中文本是否超宽**。`text-align:center` + `white-space:nowrap` 的文本向两边同时溢出，`scrollWidth` 只统计行尾那一侧，会把超宽误判成"放得下"，结果字号不缩、文字被裁掉。模板里的 `measureText()` 改用 `Range.getBoundingClientRect()` 量文本真实宽度。
8. **用 `sips` 缩图要先比宽度**。原图只比目标宽一点点时（比如 Pexels 的 `large2x` 只有 1880px，目标是 1600px），重编码只会让体积**变大**（实测 185KB → 237KB）。`找图.js` 里的 `shrink()` 加了 `cur <= width * 1.3` 就跳过的判断，缩的时候还带 `-s formatOptions 75`。
9. **忘了写 `--template` 会静默用错模板**。默认模板是老的 `信息图模板.html`，套贴图数据也能出图，但版式完全是另一套 —— 最阴的是 9 张图输出的字节数**完全一样**（都渲染同一套占比布局），不看图根本发现不了。现在 `批量出图.js` 按数据里有没有 `layout` 字段自动选模板。
10. **图片字段的路径改写要按「包含 img」匹配，不能按「以 img 开头」**。`quadImgs` 开头是 `quad`，用 `/^img/i` 会漏掉，四宫格的图就全是 404 —— 页面里表现为四个「缺图」小方块。正确写法是 `/img/i.test(k)`。
11. **别用 glob 扫 `.pages/` 决定截哪些页面**。换过模板或改过 `name` 之后，上一轮遗留的旧页面也会被捡去截图，结果是「完成 10/10 张」外加一批过期图。现在 `批量出图.js` 会写一份 `_manifest.txt`（这一轮真正生成了哪些页面），`批量出图.sh` 只按清单截。
12. **截图要写临时文件名，截完再 `mv` 过去**。原因有两个：① 目标文件已存在时，"文件大小稳定"会立刻成立，脚本误以为出图完成，直接 kill 掉 Chrome，结果拿到的是**上一轮的旧图**；② 先 `rm` 旧图能避免这个误判，但删除操作多了会撞上沙箱的批量删除保护（一次跑 9 张就触顶），整个命令被打断。临时名 + `mv -f` 两个问题一起解决。
13. **`duo` 的固定高度会把内容顶出内容区**。`duo` 里主体图、金句、四宫格全都是 `flex: none`、高度写死，加起来 569px；而内容区在「有副标题 + 页脚 3 行」时只剩约 552px —— 于是**超出 17px，盖到页脚上**。肉眼看图几乎发现不了（九版式示例里的 09 一直就是这样，直到用 `检查溢出.sh` 量出来）。已把常量收了一遍：主体图 `290 → 272`、金句上边距 `26 → 20`、四宫格上边距 `30 → 24`、格子图 `148 → 142`。**`贴图模板.html` 和 `导出SVG.js` 两处都要改**（HTML 是 CSS，SVG 是 `contentDuo()` 里的 `rowH` / `quoteH` / `thumbH` 常量），改完用 `./检查溢出.sh 输出目录` 复验。
14. **受限环境下 Chrome 必须加 `--no-sandbox`**。这台机器上 Chrome 自己的沙箱初始化会失败（`Failed to initialize sandbox: Operation not permitted` → SIGTRAP、不产出任何截图），旧版 `批量出图.sh` 会**静默失败**（只看到"没产出截图"）。现在脚本先按默认参数试一次，失败就自动退回 `--no-sandbox` 再来一次，并把结果记住、后面几张直接复用；等待循环也加了「进程已退出且没有产物就立刻收工」——否则一张白等 30 秒（120 × 0.25s），九张就直接超时被打断。渲染的都是本机生成的页面，没有外部输入。
15. **`border` 会破坏 flex 等分高度**。`band` 的留白带一开始用 `border-top/bottom: 2px`，实测三条色带高度变成 **173 / 177 / 173** —— 中间那条多 4px，正好是两个边框。即使全局有 `box-sizing: border-box` 也一样。改成 `box-shadow: inset 0 2px 0 var(--soft-line), inset 0 -2px 0 var(--soft-line)` 后回到 **175 / 175 / 175**（`box-shadow` 不参与布局）。**凡是"必须等高 / 等宽"的装配，装饰线一律别用 border。**
16. **`fitText` 在 shrink-to-fit 容器里会失效**。`bigword` 的巨型字外面套了 `.bw-box`，而它在 `align-items: center` 的 flex 列里会收缩到内容宽 —— 于是 `fitText` 里的 `el.parentElement.clientWidth` 等于字自己的宽度，"放得下"永远成立，4 个字的巨型字不缩字号、直接横着顶出画布。**让 `fitText` 生效的前提是：要量的元素的父容器必须显式撑满**（这里给 `.bw-box` 加 `width: 100%`）。
17. **设计内的满幅出血会被越界探针误报**。`bigword` 的色块垫、`band` 的色带都左右各出 50px（从 x=26 顶到 x=784，和背景装饰 blob 一样是设计内出血），`越界探针.js` 会把它们全报成越界。加 `.bleed` 类做白名单跳过。**新增任何出血元素时记得同时打上这个类**，否则探针就废了。
18. **给 `_预览.html` 量高再截图不能一次性写完**。带 `--user-data-dir` 的截图 Chrome 不会自己退出，命令会在最后一步被挂住（拿到 SIGKILL）。要照 `总览截图.sh` 的做法：后台起 Chrome → 轮询"文件大小连续两次不变" → 再强杀。另外探针页要和 `_预览.html` 放同一目录，否则 SVG 相对路径全 404、量出来的页高偏小。
