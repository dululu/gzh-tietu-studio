# 说明书 · 公众号贴图工坊

> 这份是「怎么用」。想改模板、改配色、了解排版原理，看 [`贴图排版手册.md`](贴图排版手册.md)。

---

## 一、它是什么

把一份 JSON 数据（每张图一个对象）批量渲染成 **810×1080** 的公众号贴图。数据变了版式不用重做，
因为九种版式共用同一套骨架：

```
水彩底（径向渐变 blob）
└─ 白色圆角卡片 810×1080，inset 26px，圆角 26
   ├─ 右上角账号角标 88×88          ← `badge`
   ├─ 主标题两行 72px / 58px        ← `title1` `title2`（第二行带雾带）
   ├─ 副标题 32px（可选）            ← `deck`
   ├─ 内容区                         ← `layout` 决定（九选一）
   └─ 底部来源注释 16px 灰           ← `foot`
```

产物规格：CSS 810×1080，导出 2 倍图 **1620×2160**（3:4，公众号图片消息的竖版比例）。

## 二、安装与运行环境

### 环境要求

| 依赖 | 是否必须 | 说明 |
|---|---|---|
| Node.js ≥ 16 | 必须 | 只用内置模块，**不需要 npm install** |
| Chrome / Edge / Chromium | 必须 | 无头截图；脚本会依次探测常见安装路径 |
| macOS `sips` | 可选 | 压缩下载的图片；非 macOS 自动跳过 |
| ECharts | 已内置 | `vendor/echarts.min.js`，只有 `chart` / `bar` 两个版式用到 |

### 两种用法

**A. 当普通工具用（推荐）**：把仓库 clone 到任意目录，`cd` 进去执行命令即可。

```bash
git clone <本仓库> && cd gzh-tietu-studio
./批量出图.sh examples/数据-九种版式示例.json out
```

**B. 当 WorkBuddy 技能用**：把整个目录放进 `~/.workbuddy/skills/gzh-tietu-studio/`，
之后用自然语言说「做几张贴图」就会自动加载本技能。脚本支持从任意工作目录调用——
**素材（模板、vendor、示例数据）从技能目录读，数据和产物落在你当前的项目目录里**。

### 三条命令各自的适用场景

| 命令 | 产物 | 什么时候用 |
|---|---|---|
| `./批量出图.sh 数据.json 输出目录` | PNG 2 倍图 | **默认走这条**。由终端直接调 Chrome，能绕开沙箱对子进程的限制 |
| `node 批量出图.js 数据.json 输出目录` | PNG 2 倍图 | 本机权限正常时的纯 Node 版本，行为一致 |
| `node 导出SVG.js 数据.json 输出目录` | 可编辑 SVG | 要换配色、调间距、加元素、做系列变体时 |

如果 `批量出图.js` 报「没权限启动 Chrome」，就用 `.sh`，反之亦然。两者共用同一份模板和配色。

## 三、九种版式怎么选

选版式只需要回答一个问题：**你要给读者看的是「一件东西」「一组数」还是「一个比较」？**

| 版式 | 长什么样 | 什么时候用 | `layout` |
|---|---|---|---|
| **单数字冲击** | 一个巨大数字占满内容区，下面挂说明 | 全篇只有 1 个数字是重点（133.31 万、录取率） | `stat` |
| **编号清单** | 编号卡片列表 1/2/3 条 | 结论是"几个信号 / 几个变化 / 几条建议" | `list` |
| **左右对比** | 左浅卡右深卡，各挂 4 条要点 | A 和 B 二选一（省内 vs 外省、新高考 vs 老高考） | `compare` |
| **时间轴** | 左侧年份 + 中间竖线 + 右侧事件 | 政策沿革、发展脉络 | `timeline` |
| **双轴柱线图** | 柱线双轴，末柱高亮 | 两个指标随时间走，要突出某一年 | `chart` |
| **横向条形 + 数字卡** | 横向条形，右侧并排数字对比卡 | 结论是"谁比谁多"，且要一个冲击性对比 | `bar` |
| **单图 + 图注** | 一张大图 + 一句图注 | 有一张能说明一切的图 | `photo` |
| **主图 + 圆形焦点** | 图上叠一个 480px 白圆，圈住要强调的信息 | 图里有具体数字/条件，不圈出来读者会漏 | `photoFocus` |
| **双主体 + 金句 + 四宫格** | 两个主体并置 + 一句金句 + 四格（格子里可放图） | 抽象判断要落地（"他布局了哪 4 个方向"） | `duo` |

**选择顺序**：先看手上有什么素材（有图 → `photo` 系；纯数字 → `stat`/`chart`/`bar`；
纯文字 → `list`/`compare`/`timeline`），再看想让读者记住什么（画面 → `photo`；数字 → `stat`/`bar`；
观点 → `duo`/`list`；顺序 → `timeline`）。

### 文案长度红线（写长了字会被自动缩小，观感变差）

| 位置 | 上限 |
|---|---|
| `deck` 副标题 | ≤ 15 汉字 |
| `statLabel` | ≤ 19 汉字 |
| `compare` 每栏要点 | ≤ 12 汉字（两栏各占半宽，超了必折行、两栏参差） |
| `title1` / `title2` | 各 ≤ 12 汉字，超了靠 `fitText` 缩字号 |
| `quads` 四宫格标签 | 各 ≤ 10 汉字，模板会逐格缩到单行 |

## 四、配图

### 4.1 三个图源怎么选

| 图源 | key | 适合什么 | 命令 |
|---|---|---|---|
| **维基共享资源** | 免 | **首选**，题材最广，每张都带作者+许可 | `search` / `cat` / `get` |
| **NASA Image Library** | 免 | 航天、机器人、地球影像，公有领域 | `nasa` / `nasa-get` |
| **Pexels** | 要 | **现代实拍感最好**（校园、图书馆、实验室、职场人像） | `pexels` / `pexels-get` |
| 大都会 / 克利夫兰 / 芝加哥美术馆 | 免 | 艺术与历史文物；科技题材基本没有，适合「古文字学 / 非遗 / 考古」 | 未内置 |

实测过但本机连不上的：Openverse（连接失败）、Library of Congress（Cloudflare 403）。
Pixabay / Unsplash / Smithsonian 接口通但要 key，Pexels 够用就没接。

```bash
# 维基共享资源
node 找图.js search "humanoid robot" 8      # 全文搜（自动滤掉竖图和小图）
node 找图.js cat "Humanoid robots" 8        # 按分类取，比全文搜准
node 找图.js get "File:xxx.jpg" img 1600    # 下载，打印作者/许可/许可链接/原页

# NASA
node 找图.js nasa "robot arm space station" 8
node 找图.js nasa-get "iss071e361950" img 1600

# Pexels（key 见 4.3）
node 找图.js pexels "university students campus" 8
node 找图.js pexels-get "8199659" img 1600
```

下载默认落到**当前工作目录的 `img/`**，也会自动按需压缩（原图只比目标宽一点点时不重编码，
否则体积反而变大——`sips` 默认质量比原图高）。

**偶发超时是正常的**：维基把缩略图挪到了新的 `thumb.wikimedia.org`，本机到它时不时 ETIMEDOUT。
脚本的接口查询和下载都带 3 次重试 + socket 超时，失败时会删掉半截文件（留着 0 字节同名图最坑）。

### 4.2 三个带图版式的选图要求

| 版式 | 画面位置 | 选图建议 |
|---|---|---|
| `photo` | 满宽大图，约 658×600（横构图） | 主体在中间偏上，裁掉上下都不影响 |
| `photoFocus` | 中间被 480px 白圆盖住 | **主体不要放正中**，让有辨识度的部分留在圆外一圈 |
| `duo` 主体 | 两张方图，各 320×290，按顶部对齐裁 | 主体靠上；两张色调别差太远 |
| `duo` 四宫格 | 四个小方块，各约 152×148（**接近 1:1**） | 会裁掉横图两侧；主体要在中央，或配 `quadPos` 挪进画面 |

两个最容易翻车的地方：

- **`photoFocus`**：白圆几乎盖满画面，选一张主体正好在中间的图（比如人像特写），圆一压就全没了。
- **`duo` 四宫格**：小方块是 1:1，一张 3:2 的横图只看得到中间 2/3，主体在两侧就直接消失。

**排版心得（实测对比过）**：`duo` 版式里，**大图放"场景"、小图放"特写"**。
小格子只有 152px，场景图（人 + 环境）缩下去就糊成一片；特写（一个电极帽、一片晶圆）反而认得出来。

### 4.3 Pexels key

key 不写进脚本，按顺序查找：环境变量 `PEXELS_API_KEY` → `~/.workbuddy/pexels.key` → 项目内 `.pexels-key`。

```bash
echo "你的key" > ~/.workbuddy/pexels.key && chmod 600 ~/.workbuddy/pexels.key
```

放在**用户目录**而不是项目目录，是为了不跟着项目被提交/分享出去。key 在 <https://www.pexels.com/api/> 免费申请。

### 4.4 署名与许可（重要）

**署名是许可的使用条件，不是礼貌。** 规则：

| 许可 | 能商用 | 必须署名 | 备注 |
|---|---|---|---|
| CC BY | ✅ | ✅ | 可裁剪 |
| CC BY-SA | ✅ | ✅ | 「相同方式共享」：**裁一刀就算改编，改编稿要以同样许可发布**——公众号贴图一般做不到 |
| CC0 / 公有领域 | ✅ | ❌（建议标） | 最省事 |
| CC 标 NC / ND | ❌ | — | 一律不要用 |
| Pexels | ✅ | ❌（建议标） | 不得转售原图、不得暗示照片中的人为你背书 |

实务建议：

1. **优先 CC BY / CC0 / 公有领域**（裁剪自由）。只用 BY-SA 时照常裁剪 + 完整署名，但要知道这是灰色地带；
   商业投放、品牌稿改走 Pexels 或自采图。
2. **图多的时候只列必须署名的**。`duo` 最多 6 张图，全列出来 `foot` 会涨到 4 行、把内容区顶小。
   作者名只列一次，许可名合并成一组，例如：

   ```json
   "foot": [
     "图片：维基共享资源 · Chris Hope / Laurens R. Krol / DrHughManning / Humanrobo",
     "许可：CC BY 2.0 / CC BY 4.0 / CC BY-SA 3.0 / CC BY-SA 4.0（另 2 张公有领域）",
     "专业目录来源：教育部《普通高等学校本科专业目录（2026年）》"
   ]
   ```
3. **别把开放图库的图当"现场照"**。开放图库的图多半是通用题材，不能暗示成"某某大学实拍"，
   图注写描述性文字。Pexels 的中文语境尤其差（搜"校园"出来基本是欧美校园），用了就在图注写「示意图」。

## 五、字段速查（完整）

### 所有版式通用

| 字段 | 说明 |
|---|---|
| `name` | 输出文件名（仅批量时用，不进图） |
| `layout` | `stat` / `list` / `compare` / `timeline` / `chart` / `bar` / `photo` / `photoFocus` / `duo` |
| `theme` | `blue` / `red` / `green` / `amber` / `ink`，留空默认 `blue` |
| `badge` | 右上角账号名，默认「小铭想」。≥3 字自动缩字号 |
| `title1` | 主标题第一行（72px，给背景/定性） |
| `title2` | 主标题第二行（58px，带雾带，给反差/悬念） |
| `deck` | 副标题，留空不显示 |
| `foot` | 数组，底部来源/注释，每项一行；留空不显示 |

> 标题写法：**上句不给结论，下句才给**——对应「前 14 字定生死」。五种已验证句型见排版手册第二节。

### 各版式专属字段

| 版式 | 字段 |
|---|---|
| `stat` | `statValue` 主数字、`statUnit` 单位、`statLabel` 说明、`statSubs` 底部 2 条补充 |
| `list` | `listTitle` 标题、`listItems` = `[{ "h": "小标题", "p": "一行解释" }]`，建议 3–4 条 |
| `compare` | `cmpTitle`、`cmpLeftTitle`/`cmpLeftItems`、`cmpRightTitle`/`cmpRightItems`（各 4 条） |
| `timeline` | `tlTitle`、`tlItems` = `[{ "t": "2025", "h": "小标题", "p": "一行解释" }]`，建议 4–5 条 |
| `chart` | `chartTitle`、`legendBar`/`legendLine`、`years`、`counts`、`wealth`、`highlight`（第几根柱，从 0 数）、`countAxisMax`/`wealthAxisMax`、`countUnit`/`wealthUnit` |
| `bar` | `barTitle`、`barLabels`、`barValues`、`compareLead`（`\n` 可换行）、`compareA`、`compareMid`（默认 V）、`compareLead2`、`compareB` |
| `photo` | `img`、`cap` 图注 |
| `photoFocus` | `img`、`pills` 胶囊文字（1–2 条）、`cap` |
| `duo` | `img`/`img2` 两个主体图、`quote` 金句、`quads` 四宫格标签（**必须 4 项**）、`quadImgs` 四宫格图（可选，4 项）、`quadPos` 每格裁切位置（可选） |

### 图片字段的路径规则

- 写**相对路径**时，按「数据源 JSON 所在目录 → 脚本目录 → 当前工作目录」依次查找。
  最常见的做法：数据和 `img/` 放同一个目录，JSON 里写 `"img/xxx.jpg"`。
- 写**绝对路径或网址**都支持。但**外链图不会被 SVG 内嵌**（导出时会在命令行列出来）。
- 找不到的图**不会静默变白**：会在命令行列出来，页面上渲染成虚线占位块（四宫格是「缺图」小方块）。

### `quadImgs` / `quadPos` 怎么用

`duo` 的四宫格**不给图就是「首字大卡」**（彩色底 + 1 个大字 + 标签），**给了图就是「图 + 标签」**：

```json
{
  "layout": "duo",
  "img": "img/EEG_Recording_Cap.jpg",
  "img2": "img/Clean_room.jpg",
  "quads": ["脑机科学与技术", "半导体工艺与装备", "具身智能", "海洋智能与无人技术"],
  "quadImgs": [
    "img/Brain-computer_interface_experiment.jpg",
    "img/Semiconductor_Wafer_of_Microelectronics.jpg",
    "img/TOPIO_3_3.jpg",
    "img/RoboSub_diver.jpg"
  ],
  "quadPos": ["12% center", "center", "center", "72% center"]
}
```

- 建议**四张一起给**：只给一两张时，没图的那格还是首字卡，一眼能看出是漏配还是故意。
- `quadPos` 支持 `object-position` 的写法（`0% center` 取最左、`100% center` 取最右、`center` 居中裁）。
  导 SVG 时只会保留**左/中/右三档**，要精修就在 Figma 里拖。

## 六、五套配色

配色在 `主题.js` 里统一定义，**HTML 和 SVG 两条路共用这一份**，所以不会脱节。
`theme` 字段填名字即可：

| key | 名字 | 适合 |
|---|---|---|
| `blue` | 蓝白 | 数据分析、趋势、理性陈述 |
| `red` | 中国红 · 金榜 | 高考政策、放榜、喜报 |
| `green` | 墨绿 · 理性 | 长期发展、理性建议 |
| `amber` | 暖橙 · 米色 | 志愿选择、避坑、提醒 |
| `ink` | 墨黑 · 极简 | 时评、热点、态度 |

稳妥的搭配：

| 选题类型 | 推荐版式 | 推荐配色 |
|---|---|---|
| 高考政策 / 放榜 | `timeline`、`stat` | `red` |
| 志愿选择 / 避坑 | `compare`、`list` | `amber` |
| 数据分析 / 趋势 | `chart`、`bar` | `blue` |
| 大学热点 / 时评 | `stat`、`photo` | `ink` |
| 长期发展 / 理性建议 | `list`、`compare` | `green` |

## 七、导出 SVG（拖进 Figma 二次设计）

```bash
node 导出SVG.js 数据.json svg输出
```

得到 N 个 SVG + 一个 `_预览.html`（浏览器打开一次看完）。**用鼠标直接把 SVG 拖进 Figma 画布**，进去之后：
文字是可编辑文本框、图形是可编辑矢量、**照片是已内嵌的 `<image>`**（自带圆角裁切，不用手动置位）。

- 图片内嵌前会按目标宽度压一遍（`sips`，最长 1200px、JPEG 72）。不压的话原图直塞能到几十 MB，Figma 会卡死。
- 外链图（http / data）不内嵌，导出时在命令行列出来，SVG 里留虚线占位框。
- 导入后建议做三件事：① 字体缺失就把标题换成**思源宋体 Source Han Serif**、正文换**苹方 PingFang SC**；
  ② 整张图做成 Component，以后复制实例改文字；③ 图层已按 `背景` / `账号角标` / `主标题` / `内容区-xxx` / `来源注释` 分好组。

**什么时候用哪条路**：要发布 → PNG；要二次设计（换配色、调间距、加元素、做系列变体）→ SVG。
两条路读的是同一个 JSON。

## 八、生成总览

```bash

在输出目录生成 `_总览.html`：3 列网格引用同目录 PNG，每张下方标 `layout · theme`，

  "file://$PWD/输出目录/_总览.html"
```

## 十、常见问题

**Q：出图后是空白 / 图表没出来？**
A：看两处：`vendor/echarts.min.js` 是否存在、`主题.js` 是否在脚本目录里。

**Q：命令行说成功，但图的字节数都一样？**
A：这是最隐蔽的故障——说明全部渲染成了同一个页面，多半是模板选错了。
`批量出图.js` 现在会按数据里有没有 `layout` 字段自动选模板，正常不该出现。
自查一行：`stat -f "%z" 输出目录/*.png | sort | uniq -c`，出现同一个尺寸重复 N 次就是它。

**Q：`node 批量出图.js` 报没权限启动 Chrome？**
A：改用 `./批量出图.sh`（由终端直接调 Chrome，绕开子进程限制）。

**Q：四宫格的图没显示，是四个「缺图」小方块？**
A：图片路径解析失败。检查 `quadImgs` 的路径是否相对于数据源 JSON 所在目录；
命令行里会列出具体是哪一项找不到。

**Q：`photoFocus` 的图被白圆压住了？**
A：换一张主体不在正中的图，或改用 `photo` 版式。

**Q：文字被裁掉 / 折行难看？**
A：看第三节的文案长度红线。模板会自动缩字号，但缩到下限就放开折行了。

## 十一、踩过的坑

见 [`贴图排版手册.md`](../docs/贴图排版手册.md) 第八节「十二个坑」，每条都写清了解法。最值得先看的三条：

1. **验收信号是"各图字节数互不相同"**——9 张图一样大比白屏更难发现。
2. **截图必须写临时文件名再 mv**，否则"文件大小稳定"会立刻成立，拿到的是上一轮的旧图。
3. **别用 glob 扫 `.pages/` 决定截哪些页面**，旧页面会被一起截，白出一批过期图。
