## 二、从案例里提炼出的可复用手法（按可用度排）

### A. 直接落地了（这一轮已写进代码）

**A1 · 文字图形化：让字本身成为画面主体**
- 出处：《9 组版式实验》把「谷雨」二字重构、文字成为画面主体；《BORING》把整个词做成视觉物；Brutalist 的 `One word occupying most of the poster`。
- 落法：新增版式 `bigword` —— 巨型字 210px / `font-weight: 900`（我们已有 13 个版式里最大的是 `hero` 的 54px，差了一个量级）。
- 关键判断：**只放大到"能看清"是不够的**，要放大到"字就是图"。所以 2 个字时占满 413px 宽、4 个字自动缩到 ~165px/字仍撑满整行。

**A2 · 字压色块（高亮垫 / 撞色）**
- 出处：《春节海报》「加入一个带有颜色的色块，让这个主元素更完整」；《排版中的图形构成》「主标题放大撑满画面」。
- 落法：`bigword` 里加 `.bw-pad` —— 一条 **758px 宽（左右各出血 50px，正好顶到卡片内边距外）× 0.34em 高**的主题浅色横带，压在巨型字下半段。
- 为什么是出血：不出血的色块像「文本框底色」，出血的色块像「海报」。这是这一条里最关键的差别。
- 高度用 `--wsz`（= 巨型字实际字号）算，而不是写死 px —— 否则 4 个字缩到 165px 后，色块比例就崩了。

**A3 · 水平分割 + 色带撑满**
- 出处：《9 组版式实验》「水平分割构图，大面积粉色色块」；《排版中的图形构成》「水平平均分割最简单也最饱满」。
- 落法：新增版式 `band` —— 画面切成 2–4 条**满幅出血、零间距、等高**的横向色带，色带本身就是装饰。
- 三条纪律：
  1. **零圆角、零间距**。圆角卡片是「信息图」，直角贴合的色带才是「海报」（沿用上一轮定的「直角色块 > 药丸」）。
  2. **等高**。flex 等分，不按内容长短分配高度 —— 高矮不齐就变成「表格」了。
  3. 色带细线用 **`box-shadow: inset`** 而不是 `border`：`border` 会让留白带比另两条高 4px，破坏等高（这是实测踩到的，见下）。

**A4 · 破网格：角度只用一两档**
- 出处：Rishfield「破网格只破一个元素」；电子海报教程「倾斜角度不宜过多，通常 1–2 个主导角度」。
- 落法：全图角度收敛成三档且都有归属 —— `-7°` 只给 `vs` 的 VS 徽章、`-4°` 只给 `cards` 的贴纸、新加的 `-3°` 只给 `bigword` 的巨型字。**不新增第四档**。

**A5 · 对比色撞色的分寸**
- 出处：《9 组版式实验》「配色多用对比色：红与黑、红与蓝、黄与紫」；InDesign 那篇「一个强调色用在日期/关键词/分隔线/一个超大字形上」。
- 落法：**不给 `主题.js` 加新色**（那会动到已验收的 13 张图）。撞色只在单张内实现 —— `bigword` 的色块垫用主题 `--soft`（浅色底 + 深色字成撞色），`band` 用 `--card` 深底反白 ↔ `--soft` 浅底深字交替。警示仍走固定警示红 `#CE4038`，刻意脱离主题色。

### B. 学到的、但这轮**故意没做**的

| 手法 | 出处 | 为什么没做 |
|---|---|---|
| 文字图形化到「笔画里藏画」（负形藏鲸鱼/飞鸟） | 《字里藏境》 | 要逐字手工勾勒笔画，不是 JSON 数据能驱动的；属于定制插画工作 |
| 撕纸 / Xerox 颗粒 / 网点 / 套印错位 | Brutalist 那篇 | 需要预生成纹理图；我们的骨架是「白卡 + 径向光晕」，加颗粒会破坏和已发布 13 张的一致性 |
| 文字绕排 / 沿曲线排列 | 《排版中的图形构成》 | CSS `shape-outside` 与 SVG `textPath` 两条路都要各写一遍，收益低、维护贵 |

| 未完成图形 / 极细线条补全 | 电子海报教程 | 我们的背景已有 4 个径向光晕 blob，再加细线会互相打架 |

### C. 顺手校准的既有做法

| 案例规则 | 我们现在的实测值 | 结论 |
|---|---|---|
| 主次字号至少 3:1 | `hero` 结论 54px : 补行 21px = 2.57:1 | 略低于 3:1，但结论是压在照片上的白字、底色对比极强，暂不动（会改到已验收的 2 张图） |
| 给主角两倍留白 | `bigword` 巨型字上下各留 ~70px 空白 | ✅ 成立 |
| 首尾同色收口 | `band` 3 条 = 深 / 浅 / 深；`steps` 末级反白 | ✅ 两条路都自然收口 |
| 一套配色 2–3 色 | 主题 = 底 + 深 + 浅 + 一个强调（`hlStroke`） | ✅ 没超 |

### 踩到的坑（已修，记下来免得再犯）

1. **`border` 会破坏色带等高**。留白带一开始用 `border-top/bottom: 2px`，实测高度变成 173/177/173 —— 中间多 4px。改成 `box-shadow: inset 0 2px 0 ..., inset 0 -2px 0 ...` 后回到 175/175/175（box-shadow 不参与布局）。
2. **`fitText` 拿到 shrink-to-fit 宽度就失效**。巨型字的容器 `.bw-box` 在 `align-items: center` 的 flex 列里会收缩到内容宽，`parentElement.clientWidth` 于是等于字本身宽度 → 4 个字永远不缩、直接顶出画布。给 `.bw-box` 显式 `width: 100%` 才修好。
3. **满幅出血会被越界探针误报**。色块垫和色带左右各出 50px（设计内出血，和背景 blob 同理），探针加了 `.bleed` 白名单跳过。
4. **`--dump-dom` 量预览页 + `--user-data-dir` 截图会把命令挂住**。要按 `总览截图.sh` 的「文件大小连续两次不变」判完成再收尾，别用固定 `sleep` 后一个前台命令收场。

## 四、还没落地、但值得下一轮试的

1. **`bigword` 的纯数字形态**：Brutalist 那篇专门讲 `Massive numbers for event dates`。现在 `bigword` 支持 `bwUnit`，填 `bwWord: "1.22" + bwUnit: "万个"` 就能出巨型数字，只是样板集里还没放一张纯数字的样例。
2. **`band` 的 4 条版**：现在样例是 3 条。4 条时每条 138px，正文要压到 26 汉字以内才不溢出（红线已写进文档）。
3. **正负形分割**（一个大圆色块把版面切成内外两区，圆内放主信息、圆外压角注）—— 案例里出现两次（《9 组版式实验》的圆形正负空间分割、《字里藏境》的汉字正负形），是剩下最值得做的一个版式。
4. **中心聚焦 + 压四角辅助信息**：`bigword` 目前是「上标题 / 中巨型字 / 下说明 + 数字块」，如果把 `bw-note` 和 `bwKeys` 移到画面左下 / 右下压角，会更接近案例里的海报骨架。

## 五、第四批：从"参考海报骨架"到「拆掉白卡」（2026-09-16 深夜）

### 这一轮看的是什么

用户给了两个 WorkBuddy 内置场景的分享口令（`$26708352$` / `$52609598$`，分别是
「AI 教育课海报 · 赛道经验」和「战略分享会海报 · WorkBuddy」），并说「其实可以突破限制」。

**这两个口令我这边读不到源文件** —— 场景画廊是内置的、推荐市场里搜同名也搜不到。
所以不是"照着某个文件抄"，而是照着**那一类海报的骨架**对标：一张底图铺满、大字压上去、没有白卡。

### 关键转折：上一轮被我自己划掉的"限制"，有一个是假的

第二节 B 列了 5 条"故意没做"，理由基本都是「要预生成素材 / JSON 驱动不了」。
这一轮先承认一件事：**"素材"这层限制不成立** —— 图是可以直接生成的。
于是原来被划掉的几条立刻可做：

| 上一轮划掉的 | 当时的理由 | 现在 |
|---|---|---|
| 撕纸 / 颗粒 / 网点 | "需要预生成纹理图" | 素材可以生成 |
| 负形藏画 / 定制插画 | "不是 JSON 数据能驱动的" | 生成一张底图就能驱动 |
| 中心聚焦 + 压四角 | "竖排可读性差" | 与 `cover` 的「大字左对齐 + 数字带收口」合流 |

**教训：写"故意没做"时要把"为什么不做"写清楚 —— 因为理由会过期。**
理由写"效果不好"是设计判断，写"做不到"是能力判断，后者要定期复查。

### 落地的两件事

**1 · 满幅外壳（`shell: "full"`）—— 破骨架**

不是新增版式，而是**加了一个和版式正交的维度**：16 个版式都能加。做法上最关键的一步是
**只换背景层，不动布局** —— 卡面透明、`border-radius: 0`，但 `inset: 26px` / `padding: 50px` 全留着。
因为内容边界一点没动，**溢出检查和越界探针原封不动继续有效**，不用为满幅另写一套校验。
这是这一轮最省事的一个决定。

三个类分层，是为了让"满幅"能独立于"有没有底图"使用：

| 类 | 挂载条件 | 作用 |
|---|---|---|
| `.full` | `shell:"full"` 或 `cover` | 拆白卡、去圆角、关掉四角光晕 |
| `.hasbg` | 满幅**且**有 `bg` | 底图铺满 + 上白下白中间透的淡纱 |
| `.own-title` | `cover` | 藏掉共用双行标题，把画布整个交出去 |

只写 `shell:"full"`、不写 `bg`，得到的是「无卡的纯色满幅」—— `band` 配这一档最好看。

**2 · `cover` 满幅封面 —— 破"共用标题"**

`cvBig` 左对齐 82px 大字（支持 `<em>` 行内高亮）、`cvNote` 说明、
底部一条**画布出血**的数字带（x=0 → 810）。两个刻意的选择：

- **大字故意不接 `fitText`**。`fitText` 是"先按单行量、放不下就缩"，对一句 16 字的封面大字，
  这条路会把字号一路压到下限才开始折行，字就小得不像封面了。宁可按自然折行排、
  超出时由 `越界探针.js` 明确报出来 —— **宁可报错，不要静默把字缩小**。
  （这和第五节的 `duo` 教训是同一个方向：静默降级比报错危险。）
- **色块出血、文字不出血**：数字带首末两块的内边距加到 76px，所以带里的文字仍和上面的大字左对齐。

### 踩的坑（已写进手册第八节 19–23 条）

1. **`bg` 字段名不含 `img`**，出图脚本按 `/img/i` 找要改绝对路径的字段 → 底图静静 404。
   症状是体检打「**图 0/0 张**」，第一眼很像"探针不认识新字段"，其实是**图真的没加载**。
   判断依据：同一张卡底图前后 PNG 字节数 **417KB → 2303KB**（5.5 倍）——
   这个跳变只可能来自整张画布铺了照片。
2. **满幅会改出血位置，两条渲染路要一起改**。HTML 改 CSS 就够，`导出SVG.js` 里
   `contentBigword()` / `contentBand()` 的 `rect(PAD, …)` 是写死常量，得走同一个 `bleedBox(d)`。
   漏了不报错，只有把两侧 `画布[…]` 数值并排看才发现。
3. **`.bleed` 白名单要用 `closest`**：越界探针遍历的是 `.content *` 的每一个元素，
   出血容器**里面的**子元素同样在卡外，只跳过容器本身会全报。
4. **AI 底图可能带伪文字**，目前没有自动检查手段，只能人眼过。

### 补记 · 补齐最后一种版式，顺手修掉两个台账缺陷（同批收尾）

写文档时对着版式表逐个点，才发现**想写"覆盖全部 16 种版式"是做不到的** ——
样板集 17 张里唯独没有 `photoFocus`。而"白圆盖住画面正中"这件事光看 `photo` 是讲不清的，
选图时会直接踩坑。于是从早先的 `热点0914.json` 拿回「大学开始拼算力」那张
（素材与数据都是现成的、作者也已在台账里），脚注换成新口径，样板集 17 → **18 张**、**16/16 覆盖**。

同一趟顺手查出两个**没人会主动发现的静默缺陷**，属于同一类：**配置和代码对不上，但不报错**。

1. **`examples/CREDITS.md` 的表格列序和 `署名行.js` 对不上**。`parseLedger()` 取的是
   第 1 列文件名 / 第 3 列作者 / 第 4 列许可，而 CREDITS.md 写的是 `本地文件 | 作者 | 许可 | 原页`
   —— 于是**许可名被当成作者、原页链接被当成许可**，输出成
   `配图：维基共享资源 · [CC BY-SA 3.0](…)；许可待核`。那个 `[CC BY-SA 3.0](…)` 看着还挺像回事，
   很容易一眼划过去。已把三个表统一成 `本地文件 | 原页 | 作者 | 许可`（Pexels 表 5 列），
   并在文件顶部写明**列序不能改**。
2. **`署名行.js` 只找 `配图署名.md`**，而包内 `examples/` 下的台账叫 `CREDITS.md`

## 六、下一轮候选池（2026-09-17 汇总，带推荐顺序）

第四节（第二批后）和第五节（第四批后）各留了一份清单，这里**合并去重、补上第四批新暴露的工程债**，
并按「做完能省多少事 / 风险多大」排序。**下次接着做，从 A 开始。**

### A · 工程债：三个探针还是"两步式"，该封成一键 ⭐ 先做这个

`越界探针.js` / `海报探针.js` / `svg校验.js` 现在是同一个模式：
**生成探针页 → 手动起 Chrome `--dump-dom` → 从 `<title>` 里正则提取**。
第四批跑 18 张样张，光两个探针就手工起了 **36 次 Chrome**，还得每次套一层
`while IFS= read -r p` 循环 + 一段 node 提取脚本 —— 每次改动都要重敲一遍。

要做的：照 `总览截图.sh` 的既有做法（后台起 Chrome → 轮询"文件大小连续两次不变" → 强杀），
封成三个入口 `./越界探针.sh <出图目录>`、`./海报探针.sh <出图目录>`、`./svg校验.sh <svg目录>`，
跑完直接印一张结论表。

顺带：`_probe_*.html` 用完自动清 —— 现在靠手删（本轮就清过一次 23 个残留；
没清的话探针会把旧页面一起跑，结论里混进过期卡，看起来像"多出来几张图"）。

**为什么排第一**：零设计风险，而**后面每一条改动都要用它**。成本半天，收益立刻兑现。

### B · 把现有版式用满（低风险，产出直接是可发样张）

1. **卡内形态的 `band` 补一张样张**。18 张里 `band` 只有满幅版（`18_`），白卡形态一条都没有 ——
   而 `bigword` 是两个形态齐全的（`16_` 白卡 / `19_` 满幅）。同一个版式只验了一半。
2. **满幅 × 老 9 个版式**。满幅是这一轮新加的**维度**，却只在 `bigword` / `band` / `cover` 上验过。
   主力版式（`compare` / `list` / `stat` / `timeline`）满幅下什么样没人看过 ——
   尤其 **`compare` 的深色右栏压在照片上**会不会糊。做法很轻：现有数据加一行
   `"shell":"full"` + `bg`，出对照图。

### C · 真·新版式（骨架级，成本最高）

3. **正负形圆形分割** —— 一个大圆色块把版面切成内外两区，圆内放主信息、圆外压角注。
   案例里出现过两次（《9 组版式实验》的圆形正负空间分割、《字里藏境》的汉字正负形）。
   **第四节就标了"剩下最值得做的一个版式"，一直没动。**
4. **中心聚焦 + 压四角** —— 把 `bigword` 的 `bwNote` / `bwKeys` 从"下挂"改到左下 / 右下压角，
   更接近案例里的海报骨架。

### D · 变体与素材（成本小，跟 B 一趟做掉）

5. **纯数字 `bigword` 样张**。字段早就支持（`bwWord:"1.22"` + `bwUnit:"万个"`），只是没样例 ——
   和 B1 一趟出两张。
6. **`band` 的 4 条版**。现在样例是 3 条；4 条时每条 138px，正文红线（≤26 汉字）已写进文档但**没实测**。
7. **`cover` 的第二种排法** —— "顶部压小字 + 中部大片留白"的极简版。
8. **AI 素材第二批** —— 按主题出（考场 / 图书馆 / 实验室）。要花 credits + 人眼验伪文字，
   **适合按需出、不适合囤**。

### 推荐顺序

**A → B(1+2) → D(5+6，跟 B 同趟) → C(3)**。

A 是欠下的工程债，做完立刻降低后面每一次改动的成本；B 和 D 都是"**用现有骨架验证没验过的组合**"，
风险低、产出直接就是可发的样张；C 才是真正需要大块时间的新设计。

> 另外一条**不算候选、算待办**：`photoFocus` 的新样张（`20_大学开始拼算力`）观感**需要人眼过目** ——
> 数据中心机架图是均匀排布的机柜，白圆盖住画面正中之后，圆里是否有足够干净的底托住 `pills` 文字，
> 本模型看不了图、判断不了。若嫌糊，换一张主体偏一侧的（比如 `CN_jimei_library_interior.jpg`，
> 图书馆内部书架在两侧、中间是通道，正好避开白圆）。
